# V10 terminology and software-update narrative revision

Date: 2026-08-06 (America/Los_Angeles)

## Outcome

The reader-facing manuscript now presents WrapEvoFS as a backward-compatible software and methodology update. The revised narrative is:

1. archived ADNI, AMP-AD, and CGGA analyses document the original end-to-end configuration;
2. audit of the original candidate banks identifies the absence of an explicit score-gap bound in top-three locking and objective flattening under zero truncation;
3. v0.2.0 adds regret-constrained medoid locking and an untruncated shifted-linear objective while retaining legacy-compatible reproduction paths;
4. retrospective re-locking evaluates the updated lock on archived candidate banks without regenerating GA candidates; and
5. 120 completed development-only AMP-AD searches compare the full original and updated configurations without held-out access.

## Controlled vocabulary

- **Original configuration:** the zero-truncated objective and top-three Jaccard-medoid locking used to generate the archived empirical demonstrations.
- **Updated configuration:** the v0.2.0 new-analysis setting combining the untruncated objective with regret-constrained medoid locking.
- **Legacy-compatible mode:** the package path that reproduces original behavior. This term is reserved for software compatibility and exact API identifiers.
- **Archived results:** frozen empirical outputs generated by the original configuration; they are not relabeled as updated results.

`Recommended` is not used as an empirical comparison label in the manuscript. This avoids treating an author preference as an experimental condition. `Original` and `updated` describe the chronological software configurations, while exact component names are used when only the objective or locking rule is under discussion.

## Configuration-level claim boundary

Supplementary Figure S18 and Supplementary Table S16 compare configurations that differ in both candidate generation and locking. Therefore, locked-count and locking-score differences are reported as configuration-level associations and are not interpreted as isolated causal effects of the objective or locking rule. The zero-truncation diagnostic remains informative about objective flattening along each saved search history.

## Preserved machine interfaces and provenance

No API identifier, frozen source-field name, directory name, run record, empirical value, or stable-hash rule was renamed. In particular, `legacy_zero_truncated_linear`, `untruncated_shifted_linear`, `top_k_jaccard_medoid`, and `regret_constrained_medoid` remain exact package identifiers. Frozen data fields containing `Legacy` or `Recommended` remain unchanged so that recorded hashes and scripts continue to reproduce the same source tables; the presentation builder maps them to `Original` and `Updated` for figures and LaTeX tables.

## Scientific computation boundary

This revision changes terminology, narrative order, captions, table headings, and figure rendering only. It does not rerun GA, RFECV, Direct selection, held-out evaluation, bootstrap analysis, Bayesian analysis, STABL, BLiP, locking-score estimation, or any empirical feature-selection experiment. No empirical numerical result was modified.
